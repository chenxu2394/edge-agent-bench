# INC-002: MQTT client certificate expiry

**Type:** Implemented synthetic incident in EdgeAgentBench.

**Symptom:** Telemetry publishing stops at **09:17 UTC**; messages accumulate in a local queue.

**Expected root cause:** `EXPIRED_MQTT_CLIENT_CERTIFICATE`. The publisher's mTLS client certificate expired at 09:00 UTC. The broker TCP endpoint is reachable, but the client cannot establish an authenticated MQTT session. Local queue persistence continues.

## Diagnostic evidence

| Evidence ID | Observation | Role |
|---|---|---|
| **L-013** | mTLS handshake rejected: expired client certificate | Required: specific causal failure |
| **M-013** | `mqtt_session_connected=0` | Required: failed broker session |
| L-015 | TLS reconnect fails with certificate-expired alert | Corroborating failure |
| L-014 | TCP connection to port 8883 succeeds | Network endpoint reachable |
| M-012 | `queue_persist_success_percent=100` | Persistence still working |
| M-011 | Disk at 93% utilization | Deliberate distractor; does not prove ENOSPC |
| M-014, M-015 | Zero publishes; 985 pending messages | Symptoms and backlog |

These records are returned by the two read-only incident tools using `incidentId: "INC-002"`. The exact timestamps, complete logs, and metric values are in [`data/incidents.json`](../data/incidents.json).

## Expected investigation

1. Retrieve the logs and metrics with the correct `incidentId`.
2. Identify the expired client certificate and the disconnected MQTT session.
3. Explain why TCP connectivity and working local storage do not restore authentication.
4. Cite at least `L-013` and `M-013` and distinguish cause from symptoms.
