# INC-003: MQTT publisher/consumer topic namespace mismatch

**Type:** Implemented synthetic incident in EdgeAgentBench.

**Symptom:** Downstream consumers stop receiving telemetry at **11:42 UTC**, despite successful broker acknowledgments for published messages.

**Expected root cause:** `MQTT_TOPIC_NAMESPACE_MISMATCH`. Publisher deployment 2.4.0 changed the output topic prefix to `factory/line-a/telemetry/v2`. The consumer remains subscribed to `factory/line-a/telemetry/v1/#`, so published v2 messages do not match the v1 subscription filter.

## Diagnostic evidence

| Evidence ID | Observation | Role |
|---|---|---|
| **L-022** | Publisher deploys `publish_topic_prefix=.../v2` | Required: upstream namespace change |
| **L-024** | Consumer remains on `.../v1/#` | Required: incompatible subscription |
| **M-025** | `downstream_delivered_messages_per_minute=0` | Required: observed consumer symptom |
| L-023 | Broker sends QoS 1 PUBACK for a v2 topic | Publish accepted despite missing downstream delivery |
| M-023, M-024 | 100% broker PUBACK and 120 accepted publishes/minute | Broker accepts the publisher's messages |
| M-022, M-027 | Publisher and consumer sessions remain connected | Rules against a simple disconnected-session diagnosis |
| M-026, L-026 | Successful local queue persistence | Rules against storage write failure |
| M-021, L-025 | Filesystem utilization at 93% | Deliberate distractor |
